# Participant and rooming import sources

This guide documents the workbook formats reviewed for the ski trip and the agreed import boundaries. The source workbooks contain real personal data and must stay outside this public repository. Do not commit source exports, filled rooming files, participant names, emails, phone numbers, booking references or tickets.

## Source workbooks

| Source                                          | Sheets and grain                                                                                                                      | Useful fields                                                                                                                                                                                | Import role                                                                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Validated registrations without booking details | One sheet; one row per validated booking reference                                                                                    | `Référence`, name, email, product/variation, optional manually entered `H`/`F`, booking and payment statuses, departure option and optional notes                                            | Frequent complete snapshot; source of truth for active validated registrations and current payment status                                         |
| Registrations with booking details              | `Par commande`: one row per order/reference. `Par ligne de commande`: one base product row and zero or more option rows per reference | Order reference, identity/contact, booking and payment statuses; product variation (`SKI`/`SPA`), city option and `FORFAIT SKI LUNDI` option                                                 | Infrequent detail enrichment and reference-to-option mapping; reimport when a newer detailed export is needed                                     |
| Companions and VIPs                             | One sheet; one row per staff/VIP entry                                                                                                | `Genre`, name, type, activity, third-day option, transport city and email                                                                                                                    | One-time, separately reviewed import because these rows have no booking reference; `Accompagnant` maps to companion and `Partner` to VIP traveler |
| Rooming template                                | One sheet; one row per available bed, grouped by room type and number                                                                 | Room type/number, occupant fields, non-skier, departure city, outbound/return train placement, dietary requirements, allergens, telephone and comments; trip metadata elsewhere on the sheet | Export the supplied agency-compatible format and import the returned rooming/ticket information in v1                                             |

### Format observations that affect parsing

- `Référence` is numeric in Excel but must be normalized to a string. It joins the validated-registration sheet to the order sheet and is repeated for product and option rows in `Par ligne de commande`.
- The detailed workbook's `Matricule` column is empty. In the validated-registration workbook, that column may contain a manually supplied `H`/`F` marker, but future exports may not. Neither column is a stable employee identifier.
- The detailed workbook separates order-level fields from product-option rows. Counting rows in `Par ligne de commande` as people would double-count attendees.
- The detail export distinguishes `Validée` from `En attente de validation`; payment state is separate. Do not use payment state as a substitute for validated-roster membership.
- The owner corrected the staff/VIP workbook's reversed `Nom` and `Prenom` values. Use the corrected headings and validate them against the reviewed workbook; do not retain the former swap as parser behavior.
- The owner confirmed `Partner` means VIP traveler. VIPs remain travelers and are outside the booking import flow.
- The rooming template contains room inventory and one row per bed. Room identity includes both room type and room number because room numbers repeat. The export accepts the supplied template, preserves its workbook layout and fills its existing columns.
- `FORFAIT SKI LUNDI` means the third ski day for this trip. The rooming export appends `3e jour de ski` in `Commentaires` while preserving existing comments.
- The validated roster's `Restant dû sur la commande` determines payment state: zero is paid; positive remaining due with a positive amount already paid is partially paid; positive remaining due with no amount paid is unpaid. Store amounts in minor currency units. Payment status is shown to managers only.
- The new group-transport model replaces per-person train/flight schedules. Source departure city may help assign a participant to a configured transport group, but the city-to-group mapping is not yet defined. Do not create groups or assign a participant from a text match without an explicit mapping rule.
- The source workbooks include invoice and postal-address information that is not needed for the trip profile. Import only fields required for agreed app behavior, with a clear retention policy.

## Agreed import flow

1. **Import detailed order data infrequently.** Validate both expected sheets, column names, references, statuses and product-option combinations. Store the reference as the external booking key. Later imports of an updated detail export may refresh detail-derived options without overwriting data maintained by staff or travelers.
2. **Stage each validated roster as a complete snapshot.** Join order details by `Référence`, never row position. Compare against the last accepted snapshot and report new, changed, missing, duplicate and unmatched references. The roster snapshot updates validation and payment statuses. A missing reference cancels that registration; preserve registration and account history, release the room assignment if no other active registration remains, and update the room composition.
3. **Show a reviewable diff.** Re-importing an unchanged file must create no duplicate account, membership, room assignment, ticket or request. A new reference is a new registration candidate. Never physically delete the user, registration history or staff-entered data. A reference change does not by itself identify which new registration replaces an old one.
4. **Apply one accepted snapshot atomically.** Commit the entire validated batch in one database transaction. Record the source version and import result. On failure, leave the previously accepted roster unchanged.
5. **Keep source registrations separate from login identity and traveler-entered data.** Use `(trip, Référence)` as the idempotent source-registration key. Email is a login/contact attribute, not the import deduplication key. Protect manual email changes behind manager authorization, detect collisions and preserve account history. Preserve room assignments, roles, tickets, requests and traveler profile answers unless an explicit field-specific rule applies.
6. **Import companions and VIPs once, separately.** Use the corrected name columns and reviewed role mapping: `Accompagnant` becomes companion; `Partner` becomes a normal traveler with VIP status. Joffray and Stéphane are managers. Do not grant manager role through a name match alone.
7. **Export and reimport the agency workbook without changing its layout.** The manager uploads the supplied template; the app fills the existing columns and preserves its train seat columns for the agency. On return, preview matches by normalized exact first and last name; ambiguous or unknown matches block the commit. Update only returned train-seat fields. The owner handles agency delivery and ticket imports in v1; a dedicated agency account and automatic ticket/seat assignment are deferred beyond v1.
8. **Collect and protect profile data separately.** The app may prefill sex from an available roster value, but the traveler must confirm or change it during first-login onboarding; if absent, the traveler supplies it. The only choices are man/woman, with a concise tooltip explaining that the field supports rooming controls. Collect dietary/allergen preferences and emergency contact details. Companions may view emergency contacts on profiles in their participant list; enforce trip membership and role checks server-side. Travelers may edit their profile except for email; email changes are handled by managers.

## Agreed decisions

- Payment state is manager-only and derived from the frequent validated roster's paid and remaining-due amounts. Detailed invoice status is not required for the frequent import.
- Removing a validated reference from the complete roster snapshot cancels that registration and releases the room assignment only if no other active registration for that user remains.
- Emergency contacts stay inside the app for authorized companions/managers; they are never exported to the agency workbook.
- The third ski day is written as `3e jour de ski` in `Commentaires` and existing comments are preserved.

## Import implementation

The organizer import UI uses format-specific readers with a preview and explicit commit. The validated roster joins and deduplicates by reference, derives payment status, and preserves manually maintained fields. The detail export enriches phone and options. The staff/VIP source allows explicit account matching and manager assignment. The agency return is a separate import source and changes only returned seats. Keep these readers strict to their known source formats.
