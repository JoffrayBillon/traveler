# Security and operations

This repository is public. Commit only synthetic examples. Never commit participant spreadsheets, names/emails tied to bookings, tickets, database dumps, session data, magic links, credentials, private logs, or browser state. Keep those outside the checkout; ignored directories are an extra guard, not a privacy boundary. Inspect staged diffs before publishing. Report a leak without reposting its contents; revoke exposed credentials and handle history cleanup explicitly.

Authentication is closed membership: no public signup, server-side membership and role authorization, indistinguishable public acknowledgements for known/unknown emails, database-backed rate limiting and secure session cookies. The login form enforces a 30-second cooldown; the server enforces one request per normalized email every 30 seconds using a SHA-256 email key, plus Better Auth's five-per-minute client-IP limit. The login endpoint only sends a link to an existing trip member; an imported address is not yet verified. Better Auth marks the address verified only after its single-use link is redeemed. Bootstrap the first manager through the explicit local operator command; clients cannot assign themselves privileges. Keep the auth secret and SMTP credentials in environment variables and never log sign-in links or tokens.

Future uploads need bounded sizes, type/content validation, generated storage keys and private storage. Download authorization must verify the requesting user's trip and permissions. Never place tickets in frontend public assets, Git, logs or an unauthenticated public bucket. The private storage provider and retention policy remain open decisions.

Use separate development, preview and production resources and credentials. The current feature-preview workflow has no database credentials; provision an isolated preview database before enabling them rather than sharing `traveler-dev` or production with arbitrary feature code. Deployment migrations use Vercel's environment runner so database tokens are not copied into GitHub secrets or files. Redact secrets, ticket contents and authentication links from logs. Define retention, backup and restoration checks before real traveler data is stored. An Excel rooming export does not replace a database backup. Do not silently fall back to a fake successful external response.

Dependency versions and lockfile are reviewed together. The workspace permits the specific esbuild version's required installation script only. CI jobs that execute unreviewed pull-request code receive no deployment secrets. Do not use `pull_request_target` to run a PR checkout with elevated credentials.
